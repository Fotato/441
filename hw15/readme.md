# Reflection

## Conceptual Understanding
Personally, I thought it was interesting how rendering works. I didn't really understand, but once you enter the third dimension resources get used up really quickly. I found it neat how this JavaScript library went about maintaining 3D objects. Instead of creating new objects every time they are preserved in memory. This means that you only add a single object to the scene.

## Technical Challenges
For me there were three difficult parts:

* Firstly, working with OBJ models made very little sense to me. I just didn't really get them, but I followed your instructions and got that done. Making lines and 3D shapes was a lot more intuitive.

* Second, I had to get help with the Three.js library. For the most part much of it made sense, but there were instances were I didn't fully understand what type of object I was handling considering that a lot of these 3D shapes are composed of a bunch of other objects. It got messy fast, so I had AI help me sort it out.

* Lastly, I had a lot of grief with loading the model in time. Since working in a webpage is very different than working with linear code in something like a terminal, I had to get help from AI to work out asynchronous code execution. It does make sense, and I got it to work, it just is super counterintuitive and changes how you code substantially.

## Design & Intent
I'll be honest, there was very little intention at first. But after I finished your canvas tutorial I saw a lot of opportunity. I became pretty obsessed with the lines, because I like the idea of forming inconceivable shapes. Of course a shape isn't pronounced when there is a single line and so I decided to learn about how I could make a hundred of them, all following behind like an afterimage. It was super fun. It ended up looking like an old Windows screen saver.

## Growth & Iteration
I think I would continue to make fun shapes with the lines, or if I felt especially ambitious I would make a rudimentary game.

If I were to continue to learn about Three.JS I would try an figure out how to appropriately segment the business logic of a game and the rendering. I will say, I am very interested in the underlying mechanics of a 3D engine, so maybe one day I'll see how they work.
